# maître M0 — Repo, Lounge Demo & README Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the public `danielrdg/maitre` repo with a runnable `maitre lounge --demo` (the approved v5 pixel lounge, modularized, with generative jazz/house music) and a complete, aesthetic English README.

**Architecture:** A tiny TypeScript CLI (`bin/maitre` → `dist/src/cli.js`) starts a token-gated static server on 127.0.0.1 that serves `lounge/` (plain ES modules + canvas, no build) and opens it as an app window. The lounge is split into pure-logic modules (tested with `node:test`) and thin DOM/canvas glue. README art (banner, GIF, sprite strip) is captured from the demo itself by a script using system Chrome + ffmpeg.

**Tech Stack:** Node ≥ 20 (tested on 20.19), TypeScript 5 (`tsc`, strict), `node:test`, vanilla JS canvas + WebAudio, `puppeteer-core` (dev only, asset capture), ffmpeg (asset capture).

**Spec:** `~/maitre/docs/superpowers/specs/2026-11-25-maitre-design.md` (pt-BR, local only, gitignored; Task 7 produces the English, public `docs/design.md`). Visual reference (local only, gitignored, read by absolute path from the worktree): `~/maitre/docs/mockups/lounge-v5-festa.html` (approved), `~/maitre/docs/mockups/lounge-v3.html` (history).

**Later milestones (separate plans, not here):** M1 events/daemon/SSE, M2 rooms + reception + router, M3 doorman + janitor + vault, M4 building (needs its own mockup approved first), M5 answer-from-lounge + routing feedback. Spikes 0–3 from spec §9 run at the start of M1.

## Global Constraints

- Repo name `maitre` (lowercase), owner `danielrdg`, **public**, license **MIT** (© 2026 danielrdg).
- Everything in the repo is **English**: code, comments, CLI output, docs, README. The lounge UI defaults to English; `pt-BR` is an optional UI locale (`?lang=pt-BR`).
- **No employer/personal data** in the repo: no company names, no real PR numbers, no real project names. - **Zero runtime dependencies.** devDependencies only: `typescript`, `@types/node`, `puppeteer-core`.
- Lounge: plain ES modules served as-is, **no CDN** at runtime; fonts bundled (Pixelify Sans, Silkscreen — OFL, with `OFL.txt`).
- All sprites, scenery, SFX and music are **generated by code**. No third-party image/audio assets.
- Server binds **127.0.0.1 only** and requires the session token (`?key=` once, then cookie `maitre_key`).
- Agent-sourced text is rendered with `textContent`, **never** `innerHTML`.
- Visual identity: neon pixel logotype "maître" (Pixelify Sans 700, pink neon `#ff5fa2` glow, text `#ffe0ef`), gold `#d9a441`, lacquer red `#3a130f`, ink `#140b08`.

## Review Focus

1. **Wrong/missing token or path traversal** (`/../package.json`, `%2e%2e`) → 403/404, never a file outside `lounge/`. → tests in Task 2.
2. **Port already in use** → server falls back to the next free port (up to +20) and prints the real URL. → test in Task 2.
3. **No browser / no display** (SSH session, no `DISPLAY`/`WAYLAND_DISPLAY`) → CLI prints the URL and keeps serving; never crashes. → test in Task 2 (`openApp` returns `false`).
4. **Tab hidden then shown** → no burst of queued dings/cards on resume: timers are wall-clock based and clamp `dt` to 50 ms; at most one ding per 22 s. → test in Task 3 (`DingScheduler`).
5. **Audio before a user gesture** (autoplay policy) → no exceptions; music choice made before the gesture starts on the first gesture. → test in Task 4 (`MusicController` with a fake AudioContext that starts `suspended`).
