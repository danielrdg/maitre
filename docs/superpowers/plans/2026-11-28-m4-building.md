# M4 · The Building Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the single-room lounge into a building, with three views on one canvas switched by an elevator, and themed floors that keep their number and theme:
- a facade with one floor per project that has an open room;
- a themed floor per project;
- the lobby + terrace shared by every project.

**Architecture:**
- **Places registry (first).** Every hard-coded coordinate moves into `lounge/js/places.js`, with no change in behaviour.
- **Themes.** The mockup's palettes become theme data, and the floor painters take a theme.
- **Server.** It keeps `state/floors.json` (project → floor number, theme) and sends `floors` in the SSE snapshot and as its own event.
- **Client model.** A pure `lounge/js/building.js` decides which view each agent appears in, lays out the facade and steps the elevator.
- **Rendering.** It splits into floor, facade and lobby scenes over the same world of agents.

**Tech Stack:** TypeScript (Node ≥20, strict, `node:test`) on the server; plain JS ES modules with canvas in `lounge/`; zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-27-m4-building-design.md` (local, gitignored; approved by the owner 28-11-2026). **Mockup:** `docs/mockups/building.html`, with screenshots in `docs/mockups/building-shots/`. The mockup is the target look.

## Global Constraints

- Canvas stays 576x324, crisp integer scaling, plain JS ES modules, no framework, no runtime dependency, no CDN, no third-party images or fonts (fonts from `lounge/fonts/`).
- New logic goes in pure importable modules with `node:test` tests (`test/lounge/*.test.mjs` for the client, `test/*.test.ts` for the server). Existing tests keep their meaning: update them on purpose, never loosen them.
- Theme ids (exact): `hall`, `casino`, `deco`, `tiki`, `karaoke`, `garden`. New-project pick order: `casino, deco, tiki, karaoke, garden, hall`. When all six are taken, use a stable hash of the name.
- Floors:
  - `state/floors.json` holds `{ "<project>": { "floor": n, "theme": "<id>" } }`, written atomically.
  - Entries are permanent; numbers start at 1 and are never reused.
  - The scratch floor is the entry `"scratch"`, always theme `hall`.
  - A room without `project` belongs to `scratch`.
- "Used" for the theme pick means worn by a floor open right now. The stored theme stays with the project for good.
- `config.json` `projects.<name>.theme` (one of the six ids, else warn and ignore) wins over the stored theme for display.
- Wire format:
  - The SSE snapshot gains `floors: [{ project, floor, theme, locked }]`, holding only the floors with an open room, sorted by floor.
  - `locked: true` when the theme comes from config.
  - A new SSE event `floors` carries the same array whenever it changes.
- `POST /api/floors/<project>/theme` with `{ "theme": "<id>" }`:
  - It uses the same auth / `Origin` / `x-maitre-request: 1` checks as the other lounge POSTs.
  - An unknown project or theme gets 400. A theme locked by config gets 409.
  - It writes only `floors.json`, never `config.json`.
  - The demo lounge answers 403.
- Where agents are:
  - `blocked` → lobby bell (from every floor);
  - `smoke` → terrace (from every floor);
  - `queue` → sidewalk;
  - every other state → its project's floor, with the M3b behaviour unchanged (parked dimmed on the couch, dance only at rest, orange notice balloon).
- Facade:
  - Open floors stack in floor-number order with no gaps.
  - 4 project floors fit at the mockup's geometry (42 px per floor), plus the lobby and the roof.
  - From the 5th floor on, the facade scrolls vertically.
  - The elevator lists every floor.
  - The right-hand column is the list of open floors (number, project, theme swatch); clicking a row rides there.
- Default view: the facade when there are ≥ 2 open floors, else straight onto the only floor (or the lobby when there are no floors).
- The red "needs you" chip shows in every view; clicking it rides to the lobby and opens that room's panel.
- An agent changing view walks to its view's elevator door and disappears, then appears at the destination's elevator door. Only the user's navigation moves the car.
- Music:
  - No new styles. `casino`/`karaoke` → `house`; `hall`/`deco`/`tiki`/`garden` → `jazz`.
  - The theme sets the style only while music is on and the user hasn't picked one by hand. A hand pick holds everywhere.
- The floor view's "floor N theme: … ▸" button cycles to the next theme and saves it. With `locked` it shows the theme plus "set in config" and does nothing.
- Nothing M3 may be lost in any view:
  - parked rooms, Wake, dance, notices and the PR link;
  - the panel, the reception box, Open in terminal, and the bell and its sound;
  - demo mode, and the lounge pausing while hidden.
- Demo and assets use made-up project names only (`webshop`, `api`, `mobile`, `docs`). `npm run assets` must leave a clean tree: the capture keeps today's README art by opening the `hall` floor view in capture mode, or the art is regenerated on purpose.
- Repo rules:
  - Public repo: no employer name, work email or personal paths.
  - Commits use the repo-local identity and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - Branch `feat/m4-building` in `~/maitre--worktrees/m4`.
  - Never touch the real `~/.maitre`, the live service on 8737 or the herdr session `maitre`.

## Review Focus

1. **Many floors.** A 7th open floor makes the facade scroll; every floor stays reachable through the elevator and the right-hand list, and the alert floor still blinks while scrolled out of view, with the chip still visible. Task 5.
2. **Floors that close and reopen.** A project whose last room closes disappears from the facade and comes back with the same number and theme, even after other projects opened in between. Tasks 3 and 4.
3. **A view showing no-one, or the alert hidden.** A blocked room from a floor you are not looking at still rings the bell and shows the chip. Answering it sends the room back to its floor without walking through walls. Task 5.
4. **Theme button races.** Two quick clicks, a 409 because config locked the theme, or the lounge restarting mid-click: the floor never shows a theme the server didn't save. Tasks 3 and 6.
5. **Old clients and old state.** A missing or corrupt `floors.json`, or a project renamed in the index: the lounge still draws, using rebuilt floors and a warning. It never throws on boot. Task 3.

### Task 3: Floors on the server

**Files:**
- Create: `src/floors.ts`
- Modify: `src/config.ts` (`ProjectOverride.theme`, validation with a warning), `src/live-api.ts` (snapshot `floors`, SSE `floors` event), `src/lounge-reception.ts` or `src/lounge-server.ts` (the POST route, following how `/api/reception` and the room routes are wired), `src/rooms.ts` if a helper for "open rooms by project" is needed
- Test: `test/floors.test.ts`, `test/live-api.test.ts`, `test/lounge-reception.test.ts`

**Interfaces:**
- Produces:
  - `export const THEME_IDS` (same six, in pick order `casino, deco, tiki, karaoke, garden, hall`, and a separate `isThemeId(x)`);
  - `export interface Floor { project: string; floor: number; theme: string; locked: boolean }`;
  - `export function readFloors(env?): Record<string, {floor:number; theme:string}>`. A missing or corrupt file returns `{}` plus a warning; it never throws.
  - `export function openFloors(openProjects: string[], env?): Floor[]`. It ensures an entry for every open project, writing atomically only when something changed, applies the config overrides, and returns the floors sorted by floor.
  - `export function pickTheme(taken: Set<string>, project: string): string`.
  - `export function setTheme(project: string, theme: string, env?): Floor`. It throws a typed error for an unknown project or theme, or a locked theme.
- `LiveRooms` emits `floors` when `openFloors` returns a different array from the last one sent. A room counts as open when it is not closed (`closedAt` with `closedBy`, or a closed record). Queued rooms count under their routed project; rooms without a project count under `scratch`.

  - A theme freed by a closed floor is reused by a new project, but never taken from the closed one.
  - A config override wins, with `locked: true`, and a bad override warns and is ignored.
  - A corrupt `floors.json` → `{}` plus a warning, and the next write repairs it.
